numbat-tools architecture

Three components · one loopback boundary

numbat writes the records. This is where you read them.

A Go daemon serves one HTML file and a whitelist of NDJSON over 127.0.0.1. The page parses in chunks, renders a virtual window, and never sends a byte anywhere. A Python tool trims the log on a schedule without ever losing a record. That's the whole system.

Request path

Browser to daemon to disk. Nothing leaves the machine.

The viewer never touches the filesystem directly — browsers forbid it. numbatd is the shim: it answers three routes, and everything it will serve is decided by a regex before a file handle is ever opened.

Auto-load

No file picker

On open the page calls /api/sources, gets every record file with its size, and loads the largest automatically. Falls back to scraping a directory index, then to a manual picker — so the same HTML works behind any server, or none.

Live

HEAD before GET

A served source is polled from the moment it loads — no toggle. Polling compares content-length, last-modified, and etag every four seconds and only re-downloads when one changes. Filters, time range, and the selected record survive each refresh, and arrivals land at the top of the newest-first list with a highlight.

Footprint

One small process

Static Go binary, no cgo, standard library only. Idles around 6 MB resident. launchd starts it at login and restarts it if it dies, throttled so a crash loop can't spin.

The security boundary

A localhost port is reachable from every tab you have open.

That's the actual threat model — not the network, but the browser. A page on any site can send requests to 127.0.0.1. Two mechanisms decide what happens next, and neither is authentication.

Host: 127.0.0.1:8787
GET /files/records.ndjson
200 · served

A request from the viewer itself carries a loopback Host header. It passes, and the filename is checked against the whitelist before any file is opened.

Host: attacker.example
GET /files/records.ndjson
403 · rejected

DNS rebinding points a hostile domain at 127.0.0.1 so a remote page can talk to local services. The Host header still says the attacker's domain. That's the tell, and it's checked first.

No CORS headers are ever set. A malicious page can still send a request to a localhost port — that's how the web works and no server can prevent it. But without Access-Control-Allow-Origin the browser refuses to hand the response back to the script that asked. Silence is the defense.

Bind

Loopback or nothing

The daemon parses its own listen address at startup and exits if it isn't 127.0.0.1. You cannot misconfigure it onto a network interface, even deliberately, without editing the source.

Path

Whitelist, not blacklist

Filenames must match [A-Za-z0-9._-]*.ndjson, then the resolved real path must still sit inside the data directory. Traversal and planted symlinks both fail closed. No directory listing exists.

Auth

Deliberately absent

Any process running as you can already read ~/.numbat straight off disk. A token would add ceremony without adding a boundary. The boundaries that exist — other users, other machines, hostile pages — are covered above.

Inside the page

Parse in chunks, render a window, index once.

A record stream grows without bound. Three decisions keep the page responsive whether the file holds a thousand lines or a million.

01

Chunked parse

12,000 lines per animation frame with a progress bar, so the tab never locks while JSON.parse grinds. A load token invalidates any in-flight parse if a newer file arrives, and records are built into a local array that only replaces the live one on success — a failed load leaves the previous view intact.

02

Flatten once, filter on primitives

At parse time each record is reduced to a flat shape — type, severity, rule, agent, session, timestamp as epoch ms — plus a cached lowercase copy of the raw line. Filtering is then a linear scan over strings and numbers rather than repeated object traversal, which is what makes the query box feel instant.

03

Virtual window

The list is a sized spacer with roughly sixty rows transform-positioned over it. Scrolling recomputes the slice on an animation frame. DOM cost is constant: scrolling two hundred thousand records costs exactly what scrolling two hundred costs.

04

Lazy event index

Findings reference their evidence by cited_event_ids. The id-to-index map is built on first use, not at load, so files with no findings never pay for it. That map is what turns a sequence match into two clicks from the commands behind it.

Every value reaching the DOM is HTML-escaped, including inside the search highlighter. The content being rendered is agent-generated command text — untrusted input you didn't write. A record containing an image tag with an error handler is a perfectly plausible thing for an agent to have executed, and it renders as literal text.

Retention

numbat never rotates its own output. Something has to.

The order of operations is the entire design. Archive first, swap atomically, and treat anything you cannot confidently date as something to keep.

classify in memory→ gzip the drop set→ write temp, same dir→ fsync→ os.replace
archive fails → original untouched, exit temp write fails → original untouched, exit

os.replace is atomic within a filesystem, so a crash mid-operation leaves either the old file or the new one — never a truncated log. Permissions carry across. A second run is a no-op.

Kept always

Anything undateable

Records with no timestamp field, records whose timestamp won't parse, and malformed lines that aren't valid JSON are all retained verbatim. A retention tool that silently destroys what it can't read is worse than no retention tool.

Archived

Dropped, not deleted

Removed records are gzipped into archive/ with a timestamped name before the original is rewritten. Archives themselves age out on a separate, longer window.

Verified

Counted end to end

Kept plus archived always equals the original record count. That invariant is asserted against a fixture seeded with malformed lines, undated records, and garbage timestamps.

Known edges

What this doesn't do.

Whole file in memory

The viewer loads the entire stream before rendering. A guard rejects files past 900 MB with a message rather than hanging the tab. Prune regularly and this never comes up.

Prune races live hooks

Hook processes append while prune rewrites. They're short-lived so the window is small, but a hook firing during the swap writes to the old inode. The scheduled run defaults to Monday morning for that reason.

Records are sensitive

Agent commands, prompts, project paths, hostname, and username sit in plaintext on disk. numbat redacts values before emission, but what remains is still a detailed account of what ran on your machine.

Schema will move

Built against numbat v0.1.1, record schema 0.2.0 — a format days old at time of writing. Field names in the flatten step are the first thing that breaks when it bumps.

Reload needs a handle

Served over localhost, reload just refetches. Opened as a bare file path in a browser without the File System Access API, there's no way to re-read from disk — you reopen the file.
